Enable automatic SBIR data updates

Publishing the HTML alone shows a saved snapshot.

This package contains real government award data plus the update software. The daily workflow must be enabled once to turn it into an automatically updated dashboard. The dashboard has not been deployed to your GitHub account yet.

One-time GitHub setup

  1. Create a separate public GitHub repository, with main as the default branch. Keep the existing private CEI notes repository private.
  2. Extract the ZIP and add all its contents to the repository, preserving the folder structure. It includes index.html, setup.html, scripts/, public/, and .github/workflows/update-radar.yml. All included files are below the browser upload limit; GitHub Desktop is the easiest way to preserve the hidden .github folder. On macOS, Command–Shift–Period shows hidden folders.
  3. In Settings → Pages → Build and deployment → Source, select GitHub Actions. An organization administrator may need to allow Actions or Pages.
  4. Open Actions → Update and publish SBIR radar → Run workflow. The workflow runs the safety tests, fetches official data, validates it, builds the page, and publishes it. A failed test or collection stops publication.
  5. Open the deployment URL returned by the successful workflow. The banner should say the published feed is verified, the collector timestamp should be recent, and Data quality & grouping details should show github-actions as the pipeline execution. This confirms that your setup actually ran.

Source indicators and relationship tags

The top row separates SBIR.gov data, the daily updater, and this screen’s feed connection. LOADED means an official dataset is present; ON means the corresponding published check succeeded; NOT SET means scheduling has not been verified; DELAYED or OFF flags an overdue or failed check. These are not separate live API connections to each funding agency.

Related companies are rule-based project comparisons, not verified commercial relationships. Each result shows its funded project, a connection, a distinction or evidence gap, and an exploratory question. Labels describe problem overlap, application overlap, a shared setting, different approaches, a workflow connection, a shared method, or literal shared title terms. All types rank together, with no reserved slots. The displayed project anchors every comparison. Each other company appears once using its strongest supported funded-project connection. Main title-defined outcomes and settings take precedence over incidental abstract mentions. Negated and background methods are excluded. Differences in named targets reduce the problem score. Click a label for both source excerpts, project scopes, settings, and official award-search links. Ranking weights: problem 40, use case 25, approach evidence 15, constraints 10, customer 5, proposed milestone 5. These are heuristic weights, not probabilities. Automated tests cover known semantic errors; they do not independently validate every inferred comparison.

The Pause slides button affects slide rotation. The award ticker and rule ticker keep moving independently.

How to read the status

  • Saved snapshot: updates are not connected or verified. This includes opening the HTML locally.
  • Published feed verified: the screen validated the dataset and its integrity digest. The source publication date can still be older than the collector check.
  • Collector overdue: no successful official-source check for over 72 hours.
  • Source publication overdue: the official file is more than 62 days old, even if the collector is working.
  • Connection delayed: this screen could not verify the latest published feed; retained data remains visible.

Ongoing operation

Routine award updates are automatic after setup. Occasional maintenance is still possible: GitHub can delay scheduled runs and disables public-repository schedules after 60 days without repository activity. Source schema changes or unusual data loss intentionally stop publication for review. Freshness warnings make these failures visible; they do not repair disabled external services.

The code uses Python standard libraries, official public data, and standard Linux GitHub-hosted runners. No paid data API or AI credits are required. Standard GitHub-hosted runners are free in public repositories under current GitHub policy. Use the included standard runner; do not choose paid larger runners. Hosting and provider policies can change.

Do not describe this as real-time funding news or verified competitor research. It is an automatically updated view of published SBIR/STTR award records with inferred technical peers.
